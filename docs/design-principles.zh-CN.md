# 设计原则

Agent Forge 是一个面向 Codex 的用户可控、低侵入、可组合多智能体工作流插件。它把 skills 视为 workflow 原语：可以单独调用，可以按需组合，也可以在当前任务不需要时完全不使用。

## 产品判断

智能体 workflow 应该显式且和任务规模相称。用户决定什么时候进入某个 workflow；每个 skill 只决定自身职责所需的流程。多智能体编排在能提升探索、风险覆盖、验证或综合质量时有价值，但不应成为所有请求的固定仪式。

本项目优化以下方向：

- **用户控制**：workflow 从显式 skill 调用或清晰用户意图开始。
- **低侵入性**：不安装 hook、不重写全局配置、不覆盖无关工具、不修改请求范围外的文件。
- **Skill 组合性**：每个 skill 只承担窄职责，保持稳定公开表面，并能和用户或插件中的其他 skills 共存。
- **多智能体杠杆**：当并行上下文能提升结果时，把子代理用作代码地图、测试、风险、文档研究、critique 或未来 workflow 角色的有界通道。
- **本地产物**：当持久文件能帮助人类或后续 agent 在没有隐藏对话上下文的情况下继续工作时，写入工作区产物。

## Workflow 边界

Agent Forge 资产应易于采用，也易于停止使用：

- 优先使用 `$write-plan` 这样的显式命令，而不是隐式拦截。
- 将输出保存在可预测的本地路径。
- 公共文档、manifest 和生成产物中不要包含机器专用状态。
- 通过清晰产物和已文档化行为来组合 skills，而不是依赖私有 side channel。
- 主 agent 始终负责综合、用户沟通和最终决策。
- 当当前外部事实会影响 workflow 决策时，使用官方文档和一手来源。

## 当前原语

Write Plan 是当前 workflow 原语。它探索环境、澄清意图和实现决策，并在开始执行前写入一份决策完整的本地 Markdown 计划。它默认只做规划：除计划产物之外，不修改 repo-tracked 状态。

## 路线图

后续工作应保持增量：

- 只有当新 workflow skill 解决明确的用户问题时才新增。
- 保持 skill 合同足够小，使其可以组合且不会产生意外副作用。
- 执行、review 或 release workflow 需要先明确边界，再进入实现。
- 除非多插件确有必要，否则保持单 marketplace 入口。
- 自动化应验证仓库合同，而不是增加用户 setup 成本。
